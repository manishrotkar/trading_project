# Local Project Structure

This document maps the files and folders in this workspace, describes what
each part is for, and explains how the pieces fit together.

The project has **two codebases side by side**:

1. **The root project — "Tiny To-Do"** — a pure-standard-library command-line
   to-do app (`main.py` + `todo/` package). See `README.md` for its user
   guide.
2. **A second, self-contained exercise** in `new_project/` — the `textstats`
   package with its own tests and `pyproject.toml`. It shares nothing with
   the root project.

Alongside them sit **market-data and credential tooling** (Fyers API access,
NSE probes), a local **audit suite** that guards against committed secrets,
and a number of one-off **scratch/probe scripts** used during development.

> **Note:** This workspace has grown by accretion. Many scripts at the root
> are one-off experiments rather than part of the to-do app, and several
> `__pycache__/` and `.pytest_cache/` directories are just build artifacts
> (all of those are gitignored). Nothing outside the to-do app and
> `new_project/` is wired into its tests or CLI.

## 1. The to-do application (root project)

Three thin layers; data flows through `data/tasks.json`, which is the single
source of truth between CLI invocations.

| File | Role |
|---|---|
| `main.py` | CLI. Parses `add` / `list` / `done` / `remove` via `argparse` (including `--priority`, `--order`, `--done`/`--pending`), prints results, sets the exit code. Only place that talks to the user. |
| `todo/core.py` | Pure logic on in-memory task dicts. No printing, no file I/O — easy to unit test. Rejects blank titles with `ValueError`. Supports an optional `priority` field (`high`/`medium`/`low`, default `medium`), priority/status ordering and priority/status filtering. |
| `todo/storage.py` | `load_tasks` / `save_tasks` against JSON. Missing or empty file → `[]`; malformed JSON raises. Creates parent dirs on save. |
| `todo/__init__.py` | Re-exports the core functions and the priority constants. |

Usage:

```bash
python main.py add "Buy milk"                     # add a task
python main.py add --priority high "Ship it"      # add with a priority
python main.py list                               # show all tasks
python main.py list --order priority              # pending first, high first
python main.py list --pending                     # hide completed tasks
python main.py list --priority high               # filter by priority
python main.py done 1                             # mark task 1 complete
python main.py remove 2                           # delete task 2
```

Exit codes: `0` success · `1` unknown task id · `2` bad usage/unknown
command/invalid priority. The data file defaults to `data/tasks.json` and can
be overridden with the `TODO_DATA_FILE` environment variable — which is
exactly how the tests and smoke script keep real data untouched.

## 2. Tests and quality checks

| Path | Purpose |
|---|---|
| `tests/test_core.py` | Unit tests for `todo/core.py` (ids, blank-title rejection, complete/remove) plus the priority suite (defaults, case-insensitivity, invalid values, priority/status ordering, filters). |
| `tests/test_storage.py` | Unit tests for `todo/storage.py` using `tempfile` (round-trip, parent-dir creation, malformed-JSON error). |
| `tests/test_simple.py` | Minimal sanity tests for the task functions. |
| `tests/test_token_manager.py` | Tests for `auth/token_manager.py` (write/read round-trip, expiry, atomic-replace leftovers). |
| `tests/test_fyers_credentials.py` | Tests for `fyers/credentials.py` (env-file parsing, `.env` template, redaction). Values are fake. |
| `tests/test_ltp.py` | Unit tests for `ltp.py` helpers (index lookup, LTP field building, loud failures on bad prices). |
| `scripts/run_checks.py` | Full check runner: `pip check` → all unit tests → CLI smoke test on a scratch file. |
| `run_checks.py` | Backwards-compatible shim that just forwards to `scripts/run_checks.py`. |

Run everything with:

```bash
python scripts/run_checks.py          # pip check + tests + smoke test
python -m unittest discover -s tests  # unit tests only
```

Current status: **75 tests, all passing**, and `pip check` reports no broken
requirements.

## 3. Dependencies

Standard library only at runtime; external packages are dev/test-only.

- `requirements.in` — the hand-maintained source of direct dependencies
  (`pytest >= 8.0`, `tomli >= 1.1.0` for Python < 3.11).
- `requirements.txt` — the generated lock file (pinned with `pip-compile`
  against Python 3.13), including pytest's transitive deps (`iniconfig`,
  `packaging`, `pluggy`, `pygments`) plus marker-excluded extras
  (`colorama`, `exceptiongroup`).

Regenerate the lock after editing the `.in` file:

```bash
pip install pip-tools
pip-compile requirements.in
```

## 4. Configuration and secrets handling

- `.env.example` — the **only** env file that should ever be committed. It
  documents every supported variable with placeholders:
  `TODO_DATA_FILE`, `ACCESS_TOKEN_FILE`, `FYERS_APP_ID`,
  `FYERS_CLIENT_ID`, `FYERS_ACCESS_TOKEN`, `FYERS_SECRET_KEY`.
- `.env` — your real local values; **gitignored**. There is no automatic
  loader; the credential module reads it when explicitly invoked.
- `fyers/credentials.py` — loads Fyers credentials from the local `.env`,
  with process-environment values taking precedence. Reports which keys are
  missing and redacts values in its summary output. Its tests use only fake
  credentials.
- `auth/token_manager.py` — manages a single access-token line in a file
  (default `access.txt`, overridable via `ACCESS_TOKEN_FILE`). Writes
  atomically via a `.tmp` file plus `os.replace()`; ages and rotates tokens.
  `auth_main.py` is its CLI front-end.

`.gitignore` aggressively excludes credential-style files
(`*.token`, `*.key`, `*.pem`, `secrets.json`, `credentials/`, …) in addition
to the usual runtime data, caches, and virtualenv noise.

## 5. Market-data tooling (Fyers / NSE)

Scripts for fetching quotes and option-chain data. They keep the to-do app's
data separate and write their downloads under `data/downloads/`
(e.g. `ltp.json`, `nifty50_bid_ask.json`, `nifty50_options_summary.json`,
`nse_all_indices.json`, `nifty50_option_contracts.csv`).

| Path | Purpose |
|---|---|
| `ltp.py` | Builds last-traded-price payloads; looks up indices by (case-insensitive) name. |
| `bid_ask.py` | Bid/ask quote helper. |
| `download_nifty_options.py` | **One-stop entry point**: refreshes the NSE India option-contract data, prints the open-interest report, and inventories the downloaded files. `--no-refresh` skips the network and reports from what is on disk. |
| `fetch_nifty50_options.py` | Fetches NIFTY 50 option-chain data. |
| `fetch_nifty50_option_contracts.py` | Fetches individual option contracts (CSV output). |
| `nifty50_expiries.py`, `verify_expiries.py`, `scratch_apply_expiries.py`, `scratch_expiry_refs.py` | Expiry-date discovery/verification. |
| `nifty50_options_summary.py` | Summarizes the option chain. |
| `nifty50_open_interest.py`, `scratch_file_open_interest.py` | Open-interest data. |
| `nifty50_report.py` | Assembles a combined market report. |
| `fetch_nse_indices.py` | Fetches NSE index data (`nse_all_indices.json`). |

`NSE_BLOCKED_NOTES.md` records the findings of the probe scripts below: NSE
endpoints were probed thoroughly and access is blocked from this environment
(403/TLS fingerprinting), so live NSE fetches are known to fail here.

## Data, caching, and ignore rules

- `data/tasks.json` — the to-do app's data file. Gitignored; created on
  first save. Tasks are plain dicts; `priority` is stored only when it
  differs from the default (`medium`), so old files stay valid.
- `data/downloads/` — target directory for fetched market data. Its
  `README.md` is the only tracked file there, so the folder exists after a
  fresh clone; everything else inside is ignored.
- `__pycache__/`, `.pytest_cache/` — bytecode and test-runner caches,
  ignored everywhere.

Relevant `.env` variables at a glance:

| Variable | Read by | Default |
|---|---|---|
| `TODO_DATA_FILE` | `todo/storage.py` | `data/tasks.json` |
| `ACCESS_TOKEN_FILE` | `auth/token_manager.py` / `auth_main.py` | `access.txt` |
| `FYERS_APP_ID`, `FYERS_CLIENT_ID`, `FYERS_ACCESS_TOKEN`, `FYERS_SECRET_KEY` | `fyers/credentials.py` via `fyers_main.py` | values from local `.env` (env vars win) |
